# 设计决策记录

这里是做项目时的一些取舍，主要给自己回头看用。格式比较随意，想到哪写到哪。

## D-001 数据库：先 SQLite，再切 PostgreSQL

**背景**：项目要求用 PostgreSQL + SQLAlchemy + 迁移脚本，但我本机 Postgres 没启动，不想卡在环境上。

**决定**：ORM 统一用 SQLAlchemy 2.0；开发阶段用 SQLite 文件库；交付时通过 `DATABASE_URL` 切 PostgreSQL，并补迁移脚本和 `compose.yaml`。

**理由**：D1 的核心目标是验证"不用模型也能定位失败任务"，数据库不该阻塞主线。SQLAlchemy 已经把方言差异隔离在连接层。

**代价**：SQLite 不支持 RLS 和并发写。所以租户隔离必须在仓储层做，不能假设数据库 RLS 已经兜底。

**何时重审**：做认证、租户与角色过滤（D12–D13）时，必须先在 Postgres 上复跑隔离测试。

## D-002 统一工具返回结构

**背景**：内部两份文档对工具返回结构的定义不一致。一份是 `{ok, data, evidence, error, retryable}`，另一份更复杂。

**决定**：D1 先用五字段结构实现，因为它更贴近当前需求。差异登记在这里，等后面和另一条轨道的同学对齐后再统一。

**理由**：如果两条轨道要共用 Runtime，契约必须一致，不然"架构可迁移"就站不住脚。

**待办**：对齐后把最终版放进 `packages/contracts`，两边各自记录版本号。

## D-003 种子脚本只允许写入"合成"数据库

**背景**：`seed_synthetic_data()` 会重建表结构，用于可重置的合成环境。

**决定**：写入前校验目标：内存库放行；文件库路径必须包含 `synthetic`，否则抛错拒绝执行。

**理由**：防呆。避免脚本被误指向真实数据库后清空数据。

**代价**：切换数据库时若不含 `synthetic` 字样需显式改名。这是故意的，增加一点摩擦。

## D-004 身份不由模型提供

**背景**：如果让模型传 `tenant_id` / `role`，存在被诱导扩权的风险。

**决定**：工具函数签名为 `tool(session, ctx, ...)`，`ctx` 是服务端构造的 `ToolContext`。对模型暴露的入口只含业务参数（如 `job_id`、`limit`），租户和角色在闭包里绑定。

**理由**：把权限做成"结构上不可能传错"，而不是靠提示词约束。

**代价**：D1 的 `resolve_principal()` 还是占位实现，只是按 user_id 查库。真实认证后面再接 JWT/SSO。

**验证**：`tests/test_read_tools.py::test_registry_hides_identity_parameters` 用签名内省检查。

## D-005 跨租户统一返回"不存在或无权访问"

**背景**：越权时如果返回 403，等于告诉攻击者"这个对象存在"。

**决定**：仓储层跨租户查询返回 `None`，工具层统一映射为 `NOT_FOUND_OR_FORBIDDEN`，错误消息里不带目标 ID。

**理由**：最小信息披露。内部审计可以单独记录真实原因。

**验证**：`tests/test_tenant_isolation.py` 断言错误消息中不出现目标 ID。

## D-006 合成故障开关用数据表注入

**背景**：超时、失败等异常如果写死在代码里，就是写死的 demo 分支，换案例很麻烦。

**决定**：新增 `synthetic_faults` 表，按 `(tool_name, target_id)` 注入故障。只存在于合成环境。

**理由**：故障由数据触发，评估时才能方便地换案例、加案例。

**代价**：这是测试夹具表，不属于业务模型；接真实系统前必须整表移除。

## D-007 模型选型：先用远程 OpenAI 兼容模型打通闭环

**背景**：D2 需要验证真实 LLM 的工具调用闭环。本机虽然跑了 27B 本地模型，但先不把它作为项目产出。

**决定**：D2 先用一个远程 OpenAI 兼容模型（`agnes-3.0-flash`）打通工具闭环。

**检查项**：

| 检查项 | 结论 |
|---|---|
| 能访问 | 已验证 |
| 支持工具调用 | 已验证 |
| 能返回用量 | 已验证 |
| 价格能查清 | 未核对 |

**理由**：工具闭环是 D2 的验收核心，先打通再谈成本优化。价格未核对时只记 token、不报金额，避免用别家模型的单价冒充本模型价格。

**代价**：远程调用意味着输入内容外发。本地 27B 模型是我的个人实验，不作为本项目产出，简历里也不会把它包装成模型训练经历。

**何时重审**：核对供应商单价后补 `PRICE_PER_1M_*_CNY`，再做预算核算。

## D-008 禁止静默降级

**背景**：之前 `ModelClient` 在没有 Key 或调用抛异常时，会静默吞掉异常，返回一段本地启发式伪造结果，并附带编造的 token 数和费用。这样任何"实测"都可能在零模型调用的情况下产出看似真实的完成率、时延与费用。

**决定**：
1. `ModelClient` 只做真实调用；无 Key 或调用失败一律抛 `ModelUnavailableError`；
2. 离线确定性行为必须显式选择 `OfflineStubModelClient`，它返回 `usage_source="offline-stub"`、token 与费用均为 0；
3. 单价未核对时 `pricing_verified=False`，费用恒为 0；
4. 脚本版 Agent 与模型版 Agent 分开命名，文档不混称。

**理由**：把"不许造假"做成结构性约束（类型和字段可校验），而不是靠人记得。

**代价**：原有依赖静默保底的用例需改写；离线演示必须显式声明使用桩。

**验证**：`tests/test_agent_core.py::test_model_client_without_key_raises_instead_of_faking`、`::test_offline_stub_is_marked_and_not_billable`、`::test_model_driven_agent_reports_model_unavailable`。
