# scope.md —— 项目范围与验收边界

版本：D1（2026-09-28）。本文件只锁定一条业务主线，避免范围蔓延。

> 本文件描述**计划**。哪些已实现以 `docs/progress.md` 为准。

## 1. 一句话用户问题

> "任务 IMP-104 导入失败，帮我查原因；能处理的话帮我处理。"

用户只知道"导入失败"，不知道下一步该看什么。不同失败需要不同工具：字段错误要检查文件，
服务超时要读任务状态与日志，权限问题要看允许返回的权限摘要。
模型依据观察结果选择下一步工具、提出追问或结束调查；**业务校验、权限、状态转移、执行重试仍由确定性代码处理**。

## 2. 工具清单（第一版）

### 2.1 查询工具（只读）

| 工具 | 模型可提供的参数 | 返回 | 后端强制约束 | 状态 |
|---|---|---|---|---|
| `get_import_job` | `job_id` | 状态、错误码、file_id、业务对象版本、evidence ID | **tenant 从登录身份取得，模型不可填** | D1 已实现 |
| `get_job_logs` | `job_id`、`limit` | 脱敏日志、时间、记录 ID | 限制条数与长度；过滤凭据；跨租户不可见 | D1 已实现 |
| `validate_csv` | `file_id` | 错误行、字段、错误类型 | 只读已上传 CSV；大小限制；不执行文件内容 | 未开始 |
| `search_runbooks` | `query`、`product_version` | 片段、doc_id、版本、章节、evidence ID | 检索前按租户与可见范围过滤 | 未开始 |
| `get_ticket_status` | `ticket_id` | 当前状态、版本 | 同租户且角色允许 | 未开始 |

### 2.2 受控写动作（唯一）

| 动作 | 模型可提供的参数 | 返回 | 后端强制约束 | 状态 |
|---|---|---|---|---|
| `create_ticket` | `proposal_id`（**不是**工单正文） | ticket_id、执行状态 | 审批 + 权限 + 版本校验 + 幂等全部通过才执行 | 未开始 |

**模型不能指定** `tenant_id`、`user_id`、`role`、审批状态。它们由服务端注入，不属于可自由填写的工具参数。
第一版**不暴露**任意 SQL、任意 URL 抓取、Shell 或 Python 执行工具。

## 3. 五个必须成立的行为（跨阶段验收）

1. 三类问题触发不同的工具路径（字段错误 / 服务超时 / 权限失败）。
2. 缺信息时先追问，拿到补充后能继续原任务。
3. 工具报错时有限恢复或停止，**不伪造成功**。
4. 最终结果可关联真实工具证据。
5. 跨租户访问被拒绝，且**不泄漏目标是否存在**。

## 4. 证据政策

- 工具返回值里的 `evidence[].id` 只证明**来源可定位**，**不自动证明结论得到支持**。
- 评估必须额外检查"引用内容与结论是否匹配"，不能只看引用 ID 是否存在。
- 内部审计可记录真实拒绝原因；对用户和模型只暴露必要信息。

## 5. 明确不在范围内（D1–D8 阶段）

- 不做模型微调、不做本地大模型服务、不做 Kubernetes、不自研框架。
- 不暴露任意代码执行、不做浏览器全自动操作、不做通用低代码平台。
- 不接企业 SSO、不做容灾与容量规划（属后续企业试点）。
- **不接真实企业系统，不使用真实员工数据。**

## 6. 初始执行上限（待 P3 按实测调整）

- 单 Agent 最多 8 次模型决策、10 次工具调用。
- 单个只读工具最多 2 次重试。
- 总执行预算初设 90 秒；等待人工输入不计入主动执行超时。
- 费用上限见 `.env.example`；达到上限停止自动调用。

## 7. 合成数据约定

两个合成租户：`tenant_a`（康源集团·合成）、`tenant_b`（星野科技·合成）。

| 任务 | 租户 | 失败原因 | 用途 |
|---|---|---|---|
| IMP-104 | tenant_a | INVALID_DATE（第 3 行 start_date） | 主排查线；正常诊断 |
| IMP-105 | tenant_a | MISSING_FIELD | 追问场景（同租户多候选） |
| IMP-106 | tenant_a | INVALID_DATE | 其 CSV 单元格含提示注入文本 |
| IMP-107 | tenant_a | UPSTREAM_TIMEOUT | 日志工具故障注入（TIMEOUT） |
| IMP-201 | tenant_a | INVALID_DATE | 多 Agent：格式错误 |
| IMP-202 | tenant_a | UPSTREAM_TIMEOUT | 多 Agent：暂时性故障 |
| IMP-203 | tenant_a | UPSTREAM_TIMEOUT | 多 Agent：证据缺口需补查 |
| IMP-B01 | tenant_b | INVALID_DATE | 跨租户越权测试 |

场景与期望结果的机器可读版本见 `evals/dev/initial_cases.jsonl`（由 `outputs/初始评估样例.jsonl` 转入）。
其中的 `fixture` 是**测试数据约定**，不是运行结果；工具调用顺序不固定，评估不应断言固定顺序。
